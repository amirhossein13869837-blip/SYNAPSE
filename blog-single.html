آینده‌ی CSS؛ از Container Query تا :has()

کامیار احمدینویسنده
۱۲ آبان ۱۴۰۳ ۸ دقیقه مطالعه توسعه وب

اگر پنج سال پیش به من می‌گفتند روزی با CSS خالص چیزهایی بسازیم که قبلاً به جاوااسکریپت وابسته بودند، می‌خندیدم. اما این دقیقاً اتفاقی است که افتاده: CSS دیگر ابزارِ «رنگ و خط» نیست؛ یک زبان منطقی و کامپوننت‌محور شده است.

مشکل قدیمی: «مخاطبِ استایل کیست؟»

سال‌ها تصمیم‌های استایل ما بر اساس اندازه‌ی صفحه گرفته می‌شد؛ اما کامپوننت‌ها در یک صفحه‌ی واحد، فضاهای کاملاً متفاوتی دارند. یک کارت محصول، در سایدبار باریک و در گرید اصلی، دو موجودِ متفاوت است — و Media Query از پسِ این تمایز برنمی‌آمد.

Container Query: استایلِ کامپوننت‌محور

حالا می‌توانیم بگوییم «اگر ظرفِ این کامپوننت کم‌عرض بود، خودش را مرتب کن» — فارغ از اینکه صفحه چقدر عرض دارد:

/* کامپوننت خودش به فضایش واکنش نشان می‌دهد */ .card { container-type: inline-size; } @container (min-width: 420px) { .card { display: grid; grid-template-columns: 1fr 2fr; } }

:has() — بالاخره انتخابگرِ والد!

عنوانِ آرزوی چند دهه‌ی توسعه‌دهنده‌ها: انتخابِ والد بر اساس فرزند. فرمِ که فیلد خطا دارد، بدون حتی یک خط جاوااسکریپت قرمز می‌شود:

/* فرمی که درونش خطا هست، خودش هشداری می‌شود */ form:has(input.invalid) { border-color: crimson; } /* و البته ترکیب طلایی: */ .card:has(img) { padding-top: 0; }
قاعده‌ی من ساده شده: هر جا می‌خواستم برای استایل، جاوااسکریپت بنویسم — اول یک بار CSS مدرن را چک می‌کنم. تقریباً همیشه جواب آنجاست.

کاربردهای واقعی که همین امروز استفاده می‌کنم

  • کارت‌های واکنش‌گرا در سایدبار و بدنه‌ی اصلی، با یک کامپوننت واحد
  • هاورِ والد هنگام فوکوسِ فرزند، بدون JS و بدون aria خلاقانه‌سازی
  • لیست‌هایی که وقتی خالی می‌شوند، حالت خالی خودشان را نشان می‌دهند
  • تعویض خودکار جهت‌ها در ترجمه‌های چپ‌به‌راست با logical properties

نکته‌ی مهم: پشتیبانی مرورگرها از هر دو ویژگی الان عالی است — Chrome، Safari و Firefox همه پشتیبانی می‌کنند. عذرِ «هنوز زود است» دیگر معتبر نیست!

پیش از پایان

این‌ها فقط سرِ نمایشی از دنیای CSS مدرن‌اند؛ :nth-of-syntaxهای منطقی، @scope، پالت‌های رنگ نسبی و ده‌ها چیز دیگر هم در راه‌اند. پیام اصلی این است: مرز میان «استایل» و «رفتار» دارد جابه‌جا می‌شود — و به نفعِ کاربر و سرعت است که جابه‌جا می‌شود.

اگر این یادداشت برایتان مفید بود، در خبرنامه‌ی وبلاگ عضو شوید تا نوشته‌های بعدی را از دست ندهید. حالا بروید و یک Container Query بنویسید — قول می‌دهم وابسته شوید!
